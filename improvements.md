## Future Changes & Improvements

**1. [Weakness] Naive Ticker Extraction (Regex + Stopwords) → [Proposed Fix] Financial Named Entity Recognition (FinBERT-NER) → [Integration path] Replace Regex with HuggingFace `transformers` Pipeline → [Why this improves signal]**
*   **Weakness:** Relying on the regex `\$?([A-Z]{1,5})\b` combined with a stopword filter[cite: 1] guarantees a high false-positive rate. Common English words (e.g., "ALL", "NOW", "SO") will leak through if omitted from the stopword list, artificially inflating their mention counts, while contextual tickers (e.g., "Apple" without the "$AAPL" tag) will be completely missed if they don't match the casing strictness.
*   **Proposed Fix:** Implement a financially fine-tuned Named Entity Recognition (NER) model, such as `yiyanghkust/finbert-ner`.
*   **Integration Path:** In `utils/ticker_extractor.py`, load the FinBERT-NER model using the HuggingFace `transformers` library. Run this pipeline over the normalized article text to extract entities explicitly classified as `ORG` (Organization) or `TICKER`. Cross-reference these contextual extractions against your PostgreSQL `tickers` table[cite: 1].
*   **Why this improves signal:** It shifts ticker identification from dumb pattern matching to semantic understanding, eliminating the "noise" of capitalized standard vocabulary and capturing the "signal" of natural-language company mentions.

**2. [Weakness] Inadequate Sentiment Scoring (TextBlob) → [Proposed Fix] Domain-Specific LLM Sentiment (FinBERT) → [Integration path] Swap TextBlob for `ProsusAI/finbert` → [Why this improves signal]**
*   **Weakness:** TextBlob evaluates general lexicon polarity[cite: 1]. It fails entirely on financial context. A headline like "XYZ slashes revenue guidance by 20%" might register as neutral or even positive to TextBlob if generic negative adjectives are missing, whereas a market participant knows this is wildly bearish.
*   **Proposed Fix:** Use `ProsusAI/finbert`, a BERT model specifically fine-tuned on financial text for sentiment analysis.
*   **Integration Path:** In `utils/sentiment.py`, replace the TextBlob instantiation[cite: 1]. Pass the concatenated `"{title} {content}"` string[cite: 1] into the FinBERT pipeline. Map its output logits (Positive, Negative, Neutral) to your existing `[-1.0, 1.0]` float scale[cite: 1]. 
*   **Why this improves signal:** You will stop classifying devastating financial news as "neutral," providing the ranking engine with an accurate `sentiment_24h` variable that reflects true market mechanics rather than movie-review polarity.

**3. [Weakness] Exploitable Deduplication Strategy (Exact URL) → [Proposed Fix] Near-Duplicate Detection (MinHash / LSH) → [Integration path] Implement `datasketch` in the DB Pipeline → [Why this improves signal]**
*   **Weakness:** Deduplicating solely by `Article.url`[cite: 1] completely misses syndicated news. A single press release published across Yahoo Finance, MSN, and Reuters will have three different URLs but identical text. Your system currently counts this as three separate mentions, creating fake volume spikes.
*   **Proposed Fix:** Use Locality Sensitive Hashing (LSH) via MinHash to detect semantic text similarity.
*   **Integration Path:** Import the `datasketch` Python library into your ingestion workers. As text is normalized, compute a MinHash signature for the article `content`. Store this signature as an array in a new `articles.minhash` column. Before insertion, query the database for signatures with a Jaccard similarity > 0.85. If a match is found, discard the article.
*   **Why this improves signal:** It prevents PR wires and highly syndicated articles from spoofing the `mentions_1h` velocity metric, ensuring a trending stock is driven by broad, unique market chatter rather than a single echoed press release.

**4. [Weakness] Skewed Ranking Volume (Raw Mention Counts) → [Proposed Fix] Statistical Anomaly Detection (Z-Score) → [Integration path] Rolling Standard Deviation in PostgreSQL → [Why this improves signal]**
*   **Weakness:** The ranking formula relies heavily on raw volume (`mentions_1h × 3` and `mentions_24h × 1.5`)[cite: 1]. Mega-cap stocks like TSLA and AAPL have naturally massive baseline volumes. They will permanently dominate your global top-10. Furthermore, your spike formula triggers if current mentions are just twice the daily hourly average (`> (mentions_24h / 24) × 2`)[cite: 1], meaning a micro-cap stock jumping from 1 mention to 3 will falsely trigger a 1.5x spike boost.
*   **Proposed Fix:** Rank based on standard deviations from the mean (Z-Score) rather than absolute mention counts.
*   **Integration Path:** Update the `ranking_engine`[cite: 1]. Instead of just querying the last 24 hours, calculate a rolling 7-day hourly mean ($\mu$) and standard deviation ($\sigma$) for each ticker using PostgreSQL window functions. Calculate the current hour's Z-Score: $Z = (mentions_{1h} - \mu) / \sigma$. Use this Z-Score as the primary volume weight in your formula.
*   **Why this improves signal:** It normalizes momentum. A stock only "trends" if it is experiencing a statistically significant breakout relative to *its own* historical baseline, leveling the playing field between AAPL and obscure mid-caps.

**5. [Weakness] Unweighted Sentiment Aggregation → [Proposed Fix] Source Authority Matrix → [Integration path] Weighted Average SQL Query → [Why this improves signal]**
*   **Weakness:** In step 8 of your data flow, the system calculates `AVG(sentiment)` from `ticker_mentions`[cite: 1]. This means a zero-follower Reddit post from `social_ingestor` carries the exact same mathematical weight as a deep-dive financial report from Alpha Vantage.
*   **Proposed Fix:** Apply a confidence weight to the sentiment average based on the source's historical reliability.
*   **Integration Path:** Add a `source_weight` float column to the `ticker_mentions` table[cite: 1]. During ingestion, assign weights (e.g., `alphavantage` = 1.0, `newsapi` = 0.8, `reddit` = 0.2). Modify the `ranking_engine` SQL[cite: 1] to compute a weighted average: `SUM(sentiment * source_weight) / SUM(source_weight)`.
*   **Why this improves signal:** It prevents bot swarms or meme-stock retail spam on social media from hijacking a ticker's fundamental sentiment score, anchoring the trend direction to higher-signal institutional news.

**6. [Weakness] Brute-Force Semantic Search (ILIKE) → [Proposed Fix] Vector Embeddings (pgvector) → [Integration path] Embeddings via `sentence-transformers` + pgvector → [Why this improves signal]**
*   **Weakness:** The fallback intent handler uses `ILIKE` across article text[cite: 1]. A query for "EV makers" will fail to return an article about "Tesla and Rivian automotive production" because the exact string "EV makers" is absent.
*   **Proposed Fix:** Implement vector search for true semantic understanding.
*   **Integration Path:** You are already using `postgres:15-alpine`[cite: 1]. Install the `pgvector` extension. In the ingestion pipeline, pass article text through a lightweight local model like `sentence-transformers/all-MiniLM-L6-v2` to generate a vector embedding. Save this to a `vector` column in `articles`. Update the `GET /search` endpoint[cite: 1] to vectorize the user's query and perform a cosine distance (`<=>`) nearest-neighbor search.
*   **Why this improves signal:** Users don't search in exact database strings. Vector search bridges the gap between natural language queries and latent market themes, returning highly relevant signals based on context rather than rigid keyword mapping.
